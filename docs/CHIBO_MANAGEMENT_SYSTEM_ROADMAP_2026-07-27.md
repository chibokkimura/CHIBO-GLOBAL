# CHIBO 글로벌 점포관리 시스템 단계별 업데이트 계획

작성일: 2026-07-27  
운영 사이트: https://chibo-global.vercel.app/  
운영 DB: Supabase `CHIBO global MG`

## 목표

현재의 일일 매출보고 사이트를 각 점포의 월마감, 실제 원가, 이론 원가, 인건비, 로열티 및 본사 분석까지 연결되는 관리 시스템으로 확장한다.

기존 `sales`, `sale_items`, `sale_set_items` 데이터는 유지한다. 새 기능은 별도 테이블과 별도 화면으로 추가하고, 각 단계마다 Preview 검증 후 운영에 반영한다.

## 총 9회 업데이트

### 업데이트 1 — 운영 데이터 보호와 회귀검사

- 운영 DB 구조와 행 수 기준선 저장
- 데이터베이스를 수정하지 않는 읽기 전용 검사 추가
- 매출 중복, 판매상세 고아 데이터, HQ 계정 제한 검사
- 릴리스 전후 동일 검사 의무화
- 완료 기준: 기존 데이터 감소 0건, 중복 0건, 고아 데이터 0건, HQ 1개

### 업데이트 2 — 로그인·권한·RLS 안정화

- 공개 호출이 불필요한 `SECURITY DEFINER` 함수의 실행권한 회수
- OWNER와 HQ 정책을 `authenticated` 역할 기준으로 명시
- 중복된 `app_users`, `stores` 정책 정리
- HQ는 `chibo.global.mgsystem@gmail.com`만 허용
- OWNER는 연결된 점포 데이터만 조회·수정 가능
- 완료 기준: 기존 447건이 관리자와 해당 점포 오너에게 동일하게 보이고, 다른 점포와 다른 HQ 계정에서는 보이지 않음

### 업데이트 3 — 화면 구조와 사용 흐름 정리

- 오너 화면: `오늘 매출보고`, `월마감`, `원가·재고`, `직원·인건비`로 단순화
- 관리자 화면: 국가 → 점포 → 월 단위로 동일한 정보구조 적용
- 단품 메뉴와 코스·세트 메뉴를 명확히 분리
- 입력 누락과 다음 할 일을 첫 화면에서 표시
- 완료 기준: 기존 매출 입력·조회 동작 유지, 모바일과 PC에서 핵심 업무가 2단계 안에 접근 가능

### 업데이트 4 — 월마감 업무와 매출전표

- 월마감 체크리스트
- 세무 일정
- 매출전표 상세와 결제수단
- 마감 전 누락 경고
- 완료 기준: 엑셀 `月次決算日程表`, `稅務行事曆`, `銷項明細`, `提醒事項`의 핵심 업무가 화면에서 확인 가능

### 업데이트 5 — 매입·소액현금·주재료·부재료 재고

- 매입전표와 공급처
- 소액현금 입출금 및 잔액
- 재료 구분, 구매단위와 기준단위 환산
- 월초재고, 매입, 폐기·조정, 월말재고
- 완료 기준: 엑셀 매입합계와 시스템 매입합계 일치, 재고 롤포워드 일치

### 업데이트 6 — 실제 원가율

- 실제 원가 = 월초재고 + 당월매입 - 월말재고
- 실제 원가율 = 실제 원가 / 순매출
- 목표 원가율, 전월 대비, 이상치 경고
- 완료 기준: 엑셀 `銷貨成本表04`와 동일 월의 실제 원가가 일치

### 업데이트 7 — 레시피 이론원가와 인건비

- 재료단가 이력
- 메뉴별 g·ml·개 단위 레시피
- 코스·세트 구성 반영
- 이론 사용량과 실제 사용량 차이
- 근무시간, 초과근무, 급여, 인건비율
- 완료 기준: 대표 메뉴와 대표 코스의 수기 계산 결과와 시스템 결과 일치

### 업데이트 8 — 관리자 통합분석과 로열티

- 국가별·점포별·월별 매출
- 현지통화와 엔화 동시 표시
- 원가율, 인건비율, 원가+인건비율
- 메뉴별 수익성, 재료별 차이, 개선 우선순위
- 로열티 자동 계산
- 완료 기준: 관리자 화면의 합계가 점포 월마감 합계와 일치

### 업데이트 9 — 엑셀 완전출력과 전점포 전개

- 원본 양식의 모든 시트, 서식, 병합, 열너비, 인쇄설정 유지
- 시스템 데이터만 지정 셀에 입력
- 파일 열기 복구 경고 0건
- 대만 직영점 검증 후 한국·필리핀·베트남 순서로 활성화
- 완료 기준: 원본과 시트별 육안 비교 통과, Excel 복구 메시지 없음, 전점포 운영 체크리스트 통과

## 각 업데이트의 고정 절차

1. 운영 데이터 읽기 전용 기준선 기록
2. `codex/<작업명>` 브랜치에서 한 기능만 구현
3. 로컬 빌드 및 자동검사
4. Vercel Preview에서 관리자·오너 양쪽 확인
5. Preview DB 또는 테스트 점포에서 입력·수정·새로고침 확인
6. 운영 반영
7. 운영 데이터 읽기 전용 재검사
8. 데이터 감소 또는 권한 이상이 있으면 즉시 롤백

## 데이터 보호 원칙

- 기존 매출 테이블 삭제·이름변경 금지
- `DROP TABLE`, `TRUNCATE`, 기존 데이터 일괄 `DELETE` 금지
- 새 기능은 새 테이블로 추가
- 공개 스키마의 새 테이블은 RLS 활성화
- OWNER는 연결된 점포만, HQ는 지정된 관리자 계정만 접근
- 데이터가 안 보이는 현상도 데이터 유실과 동일한 장애로 취급
- DB 변경과 UI 변경을 한 배포에서 과도하게 섞지 않음
