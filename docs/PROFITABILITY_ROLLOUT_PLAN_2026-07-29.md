# CHIBO 점포 손익관리 안전 업데이트 계획

작성일: 2026-07-29

진행상태: 1~5회차 완료 · 6회차 운영 전 사용성 정리 검토 브랜치 구현 완료

## 목표

기존 매출·재고·레시피 데이터를 보존하면서 오너의 입력 부담을 최소화하고, 본사가 점포별 개선 방향을 지도할 수 있는 공통 손익관리 기능을 추가한다.

관리 기준은 국가별 법정 회계이익이 아니라 다음과 같은 점포 관리이익이다.

`순매출 - 식재 원가 - 인건비 - 매출연동 수수료 - 수도광열비 - 기타 운영비 - 임차비 - 로열티`

## 총 6회 업데이트

### 1회차 — 손익 데이터 안전 기반

- 기존 테이블을 수정하지 않고 손익 전용 테이블 2개 추가
- 본사 전용 점포 기본설정과 목표율 저장
- 월별 고객 수·총인건비·총근무시간·수수료·수도광열비·기타 운영비 저장
- OWNER는 자기 점포만, HQ는 지정 관리자 계정만 접근
- 승인된 월은 오너가 수정하지 못하도록 데이터베이스에서 차단
- 기존 데이터 입력·변경 없음

### 2회차 — 오너 월간 간편입력

- 구현됨: 월마감 화면에 월 1회 입력하는 간편 손익 섹션 추가
- 구현됨: 필수 입력은 총인건비·총근무시간·수수료·수도광열비·기타 운영비
- 구현됨: 고객 수는 POS 집계가 있는 점포만 입력
- 구현됨: 빈 값과 실제 0원을 구분
- 구현됨: 부분 저장과 입력완료 상태 자동판정
- 구현됨: OWNER 입력·HQ 읽기 전용·제출/승인월 잠금
- 검증됨: 데스크톱·모바일 배치, 저장상태, 새로고침, 월 변경, 숫자 유효성
- 안전조치: 전점포 설정이 완료되기 전까지 기존 월마감 제출을 차단하지 않음

### 3회차 — 본사 점포 기본설정과 자동계산

- 구현됨: 본사가 점포별 임대료·공용관리비·판매세 처리방식·기본 수수료율 등록
- 구현됨: 점포별 고정값과 목표율을 모든 월 계산에 자동 재사용
- 구현됨: 기존 매출·실제 식재 원가·로열티와 월 입력값을 읽기 전용 손익 뷰에서 결합
- 구현됨: 식재 원가율·인건비율·프라임코스트율·관리이익률 자동 계산
- 구현됨: 고객당 매출과 근무시간당 매출 계산
- 구현됨: 본사 목표 대비 인건비·프라임코스트·관리이익률 차이 표시
- 안전조치: 설정·월 운영비·재고마감·매출 중 하나라도 빠지면 최종 관리이익을 0으로 표시하지 않음
- 안전조치: 기존 운영 테이블의 행을 추가·수정·삭제하지 않는 `security_invoker` 요약 뷰 사용

### 4회차 — 저부담 파일 가져오기

- 구현됨: POS·근태·급여·운영비 CSV/XLSX/XLS 파일 읽기
- 구현됨: 워크시트와 헤더 행을 선택하고 대상 항목별 열 연결
- 구현됨: 합계·마지막 값·최댓값 집계 방식 선택
- 구현됨: 합계/소계 행 자동 제외로 중복 합산 방지
- 구현됨: 처음 5행과 인식·제외 건수, 적용 예정 월 합계를 저장 전에 미리보기
- 구현됨: 점포·자료종류별 열 연결 규칙을 저장하고 동일 형식의 다음 달 파일에 재사용
- 구현됨: 확인 체크 후 선택한 항목만 기존 월 합계에 병합하고 미연결 수동값은 보존
- 구현됨: 원본 파일을 10MB 제한 비공개 버킷에 별도 보관하고 HQ가 감사용으로 열람
- 구현됨: 파일 해시·적용 합계·열 연결·적용자·적용시각을 변경 불가 이력으로 기록
- 안전조치: 같은 파일의 같은 월 중복 적용을 데이터베이스에서 차단
- 안전조치: 제출·승인월은 OWNER 가져오기를 데이터베이스에서 차단
- 안전조치: 파일 적용은 단일 트랜잭션으로 처리하고 실패하면 업로드 원본도 정리
- 안전조치: 자동연결이 맞지 않으면 열을 직접 선택하거나 기존 월 합계 수동입력으로 복귀

### 5회차 — 본사 통합분석과 개선지도

- 구현됨: 기존 HQ 국가 → 점포 → 월 필터와 연동한 읽기 전용 손익분석 섹션
- 구현됨: 점포 실행용 현지통화와 본사 비교용 JPY 추정액 동시 표시
- 구현됨: 순매출·식재 원가·인건비·수수료·임차비·관리이익 비교
- 구현됨: 고객당 매출과 근무시간당 매출 표시
- 구현됨: 관리이익률과 점포별 목표율 비교 그래프
- 구현됨: 손실·식재 원가·인건비·기타 비용·미입력 항목을 원인별로 판정하고 HQ의 첫 조치 3개 표시
- 구현됨: 개선항목에서 해당 점포의 월마감 또는 원가·재고 화면으로 바로 이동
- 안전조치: 계산 준비가 안 된 점포는 관리이익 0으로 취급하지 않고 누락 항목을 표시
- 안전조치: 국가 공통 목표를 새로 강제하지 않고 기존 점포별 목표율만 사용
- 안전조치: 이번 단계는 기존 테이블과 계산 뷰를 읽기만 하며 데이터베이스 쓰기·스키마 변경 없음

### 6회차 — 점포별 연결검증과 운영반영

- 구현됨: 오너 첫 화면을 Daily task·Month-end task·Setup & maintenance로 분리
- 구현됨: 월마감을 월 합계 입력 → 재고마감 → 결과 확인·제출의 3단계로 안내
- 구현됨: 수동 월 합계 입력을 기본 흐름으로 표시
- 구현됨: 파일 가져오기를 기본 접힘 상태의 선택·고급 기능으로 변경
- 구현됨: 각 단계에 Done·Next·Waiting 상태와 바로가기 제공
- 구현됨: 메뉴별 판매수량 입력에서 카테고리 합계를 자동 생성하여 중복입력 제거
- 구현됨: 재고마감 전 실제 원가율·목표달성·레시피 원가를 최종치로 표시하지 않음
- 구현됨: 실제 제출·승인 전에는 월마감 3단계를 완료로 판정하지 않음
- 구현됨: 월 합계·재고·본사 설정·수익성 결과가 미완료이면 제출 차단
- 구현됨: 모바일 재고마감을 재료별 카드 입력 방식으로 제공
- 구현됨: 모바일 하단 메뉴에 짧은 글자 라벨 추가
- 구현됨: 누락 보고서·영수증 12건 초과 시 나머지 전체보기 제공
- 구현됨: 화면 전환 시 새 화면의 맨 위에서 시작
- 안전조치: 데이터베이스 구조와 기존 저장 형식은 변경하지 않고, 과거 카테고리 수량도 손실 없이 호환
- 대만 직영점에서 전체 흐름 검증
- 각 국가 POS·근태·급여 자료 형식 확인
- 공통 파일연결이 가능한 점포부터 활성화
- 자동연결이 어려운 점포는 월 합계 입력으로 운영
- 단계별 운영 데이터 기준선 재검사 후 최종 배포

## 고정 데이터 보호 절차

1. 작업 전 운영 행 수와 권한 기준선 저장
2. 기존 테이블의 `DROP`, `TRUNCATE`, 일괄 `DELETE` 금지
3. 새 기능은 새 테이블과 새 화면으로 추가
4. 모든 공개 테이블에 RLS 적용
5. 각 단계에서 로컬 빌드와 정적검사
6. Preview에서 OWNER·HQ 권한과 저장·새로고침 검증
7. 운영 반영 전후 행 수·중복·고아데이터 재검사
8. 한 단계가 확인되기 전 다음 단계를 운영에 반영하지 않음
